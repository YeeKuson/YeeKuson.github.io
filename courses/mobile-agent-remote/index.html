      这是一篇碎碎念，飞书版与微信版使用同一份正文。

      这节是我在 WorkBuddy 时发现了一个很有意思的功能：助理，也就是手机遥控，没错，就是今年年初openclaw火的时候那个：用手机就能操控AI的功能。

      它可以把电脑上的 WorkBuddy 接到微信、企业微信、QQ、钉钉、飞书等消息工具里。腾讯官方的解释很直接：你在手机上发一条消息，电脑上的 WorkBuddy 执行任务，再把结果回复到手机上。腾讯 WorkBuddy「助理（远程任务）」官方说明

      说白了，以后临时想让 Agent 干点什么，不一定非得重新坐回电脑前。

      我自己试了一下，WorkBuddy 当前界面里一共有六个远程入口。它们最后都会汇入主界面的同一个助理对话框。官方文档也明确写了：远程指令集中在一个会话里处理，而且电脑必须保持开机并运行 WorkBuddy。具体入口数量和名称可能继续随版本变化，所以这里不做一张很快会过期的工具表。

      微信最简单，扫码就行

      如果你只是想体验一下，我建议先用微信。

      打开 WorkBuddy 左下角头像，进入：

      设置 → 助理设置 → 微信助理

      然后用微信扫码绑定即可。腾讯官方当前要求 WorkBuddy 不低于 4.6.4、手机微信不低于 8.0.70；具体版本要求以后可能变化，操作前直接看官方页面最稳。腾讯 WorkBuddy「微信助理」官方说明

      绑定完成以后，你可以先发一句最简单的话：

      你好，只回复“连接成功”，不要执行其他操作。

      如果手机能收到回复，说明最基本的消息链路已经通了。

      飞书稍微麻烦一点

      飞书需要先去飞书开发者平台注册一个机器人。

      这部分我之前已经在飞书文章《💻 Windows 纯代码流！OpenClaw 无痛接入飞书保姆级教程（JSON直连版）》里完整写过了，这里不再重复做一遍保姆级教程。

      在 WorkBuddy 里，核心就是把机器人的 App ID 和 App Secret 填进对应位置，然后完成连接。

      其中 App ID 一般以 cli_ 开头；App Secret 是私密凭证，绝对不要发进普通聊天、截图、课程文件或 Git 仓库。

      这个独立对话框，到底能调用什么？

      这里需要把 WorkBuddy“助理”的功能边界讲清楚。

      它确实是一个独立的对话框，不是我们平时在主界面里打开的项目对话。但它并不是一个什么都不知道的空白 AI：它同样会识别我们已经配置好的全局 AGENTS.md。后面如果再给 WorkBuddy 配好 Skill 和 MCP，这个对话框里同样可以使用。

      也就是说，手机遥控并不只是把一个普通聊天框搬到微信或飞书。你在电脑端已经给 WorkBuddy 配好的规则、工作方法和外部工具，也可以从这个手机入口调用。

      这是不是让你想到了 OpenClaw？

      OpenClaw 刚出来的时候，最火的能力之一不就是远程遥控吗？人在手机上发消息，电脑端的 Agent 真正执行任务。现在 WorkBuddy 把这条体验直接做进了桌面产品，还能连接微信和飞书。你不用先折腾一整套复杂环境，就可以更低门槛地体验这个超级方便的功能。

      而且，手机遥控并不只是为了炫技，它确实有真实的业务需求。

      比如公司里有些业务部门需要用 AI，但人不可能随时把电脑带在身边。在公司制度和数据权限允许的前提下，完全可以让工位上的电脑保持开机、联网并运行 WorkBuddy，人离开工位以后，再通过手机下达任务、查看结果。

      当然，它仍然不是脱离电脑独立运行的云端机器人，也不是远程桌面。电脑一旦关机、断网或者退出 WorkBuddy，远程任务就无法继续。第一次使用时，也建议先从读取文件、查询状态和生成总结开始，不要直接远程执行删除文件、批量修改项目或者发送外部消息等高风险操作。

      至于手机遥控还能完成哪些更方便、更贴近真实业务的操作，我会在最后一节课里举具体例子。

      不过不过，其实腾讯的WorkBuddy有手机版，因为我天天抱着电脑工作，没有手机远程的需求，所以没有用过手机版WorkBuddy，如果你有远程需求，也可以试试手机版WorkBuddy.
